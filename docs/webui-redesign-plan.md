# LinkLake Web UI 集中改版清单

状态：待实施  
记录日期：2026-08-01

本文记录已经确认的 Web UI 改版要求。后续应集中完成设计、开发、浏览器验证和部署，不在本轮逐项修改。

## 1. 宽屏布局

- 解决桌面宽屏下页面左右存在大量空白的问题。
- 将主工作区最大宽度由当前 `1640px` 提高至约 `2200px`，同时保留合理的动态页边距。
- 侧栏宽度由 `246px` 调整至约 `220px`，主内容区充分利用剩余空间。
- 大于 `1800px` 时，详细指标卡使用三列；普通桌面使用两列；移动端使用单列。
- 顶部和侧栏不重复展示完整品牌信息，只保留一个主要品牌入口。
- KPI 卡片在宽屏使用五列，避免第五张卡片单独换行并留下大片空白。

## 2. 顶部工具栏

- 将“服务在线、更新时间、刷新、当前用户”从页面标题右侧移动到全局顶部工具栏。
- 与现有“外观、语言”按钮放在同一行。
- 推荐顺序：`服务状态 → 更新时间 → 刷新 | 外观 → 语言 → 当前用户`。
- 顶部工具栏保持吸顶；内容标题区只显示页面标题和说明。
- 更新时间降低视觉权重，刷新按钮缩小为图标加文字。
- 移动端隐藏完整更新时间，只保留状态、刷新、外观、语言和头像。

## 3. 当前用户菜单

- 删除用户菜单中重复的“外观”和“语言”入口。
- 当前用户菜单仅保留：
  - 当前用户名、角色、认证类型和会话到期时间；
  - 修改密码；
  - 退出登录。
- 外观和语言只在顶部工具栏保留一个入口。

## 4. 用户与权限管理

- 在侧栏增加“系统管理”分组，包括：
  - 用户管理；
  - 安全与会话；
  - 审计日志。
- 用户管理支持创建、编辑、启用、停用、搜索和角色筛选。
- 支持管理员重置密码、首次登录强制改密、撤销全部会话。
- 禁止删除或停用当前用户以及系统中的最后一个管理员。
- 首期角色：
  - 管理员：全部权限；
  - 运维人员：管理客户端和转发策略，但不能管理用户和安全设置；
  - 审计人员：只读查看指标、策略和审计日志。
- 后端同步增加多用户数据库模型、角色权限校验、用户管理 API 和会话撤销能力。

## 5. 服务健康度表达

- 删除含义不直观的 `在线数/总数` 分数形式，例如 `8/11`。
- 改为明确展示：`在线、离线、停用、总计`。
- 推荐紧凑形式：`8 在线 · 3 离线 · 0 停用`，下一行显示 `共 11 条策略`。
- 使用绿色表示在线、橙色表示启用但离线、灰色表示停用。
- “已启用”和“在线”必须分别解释，避免将启用状态误认为服务已经可访问。

## 6. 流量历史时间范围

- 将现有 `5m、15m、1h、6h、24h` 改为：
  - `1h`
  - `12h`
  - `1d`
  - `7d`
  - `30d`
- 默认范围使用 `1h`。
- 后端历史保留时间同步扩展到 30 天，不能只更换前端按钮。
- 采用分层采样或降采样，避免按 5 秒间隔直接保存 30 天数据造成过高内存占用。
- 长周期图表最多返回约 300 个点，并根据范围自动选择采样步长。
- 更新中英文说明、API 范围校验、历史保留字段和相关自动化测试。

## 7. 图表重构

- “协议活动”由竖向柱状图改为横向占用图，显示当前值、上限和在线策略数。
- “故障概览”使用具有语义的颜色：警告为黄色、故障为橙色、严重错误为红色、无数据为灰色。
- 统一顶部故障总数与分类统计口径；若分类允许重复计数，必须明确说明。
- 详细协议卡片调整为三层：
  1. 核心活跃数量与健康状态；
  2. 入站/出站流量及迷你趋势图；
  3. 非零异常指标。
- 异常全部为零时仅显示“无异常”，不再展示大量空进度条。
- 主趋势图区分入站、出站、连接/会话和请求/错误，不将不同单位混用同一纵轴。
- 图表支持悬停查看时间、准确数值和指标说明。

## 8. 可读性与响应式要求

- 正文字号提高至 `13-14px`，图表标签至少 `11-12px`。
- KPI 数字使用 `24-28px`，入站和出站必须带方向标识。
- 数值直接显示在条形图末端，避免用户依靠轴线估算。
- 保持跟随系统、浅色、深色及现有多套配色主题兼容。
- 在 390px 移动端、普通桌面和 2048px 以上宽屏分别进行无横向溢出验证。

## 9. 建议实施顺序

1. 完成顶部工具栏和宽屏网格调整。
2. 重排 KPI、服务健康度和详细指标卡片。
3. 重构协议活动、故障概览和流量趋势图。
4. 实现 30 天历史指标的分层保留和 API。
5. 实现多用户、角色权限和会话管理。
6. 完成中英文、主题、桌面与移动端浏览器验收。

## 10. 完成标准

- 所有已确认项目均已实现，不能只增加不可用的菜单或按钮。
- 用户管理必须有完整后端权限校验，不能仅依赖前端隐藏操作。
- `7d/30d` 必须能返回真实历史数据，而不是重复、填充或伪造数据。
- Web UI 自动化覆盖账户菜单、用户权限、五个历史范围、八类转发策略编辑和响应式布局。
- Rust 测试、Clippy、Release 构建和真实 Chrome 冒烟测试全部通过后再部署。
