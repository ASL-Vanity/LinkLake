# ADR 0001：通用 TCP 数据面暂不切换为 QUIC

- 状态：接受
- 日期：2026-08-01

## 背景

LinkLake 已在 UDP relay 和 Iroh P2P 中使用 QUIC。另一种方案是把 TCP、HTTP、SNI、Secret、SOCKS5 和 HTTP Proxy 的所有字节流也复用到一条通用 QUIC 连接。

## 决定

本版本保留“TLS 控制连接 + 每条业务连接独立 TLS 数据连接”的通用 TCP 数据面，QUIC 继续用于原生数据报和 P2P 场景。未来可增加显式可选的 TCP-over-QUIC 传输，但不得替换 TCP/TLS 回退路径。

## 原因

- 企业网、运营商和部分云防火墙会阻断或严格限速 UDP；强制 QUIC 会降低 LinkLake 最重要的网络可达性。
- 当前每条公网连接拥有独立 TCP/TLS 数据连接，不存在把多个业务流复用进单 TCP 连接造成的跨流队头阻塞。
- 将应用 TCP 流封装进 QUIC 会形成内外两层可靠传输和拥塞控制，弱网下可能产生不必要的重传与延迟放大。
- 新增一套通用数据面会扩大协议状态、证书、迁移、回退和跨平台验收矩阵；在没有可量化收益前不应成为默认路径。

## 后续条件

只有在具备自动 UDP 可达性探测、无损 TCP/TLS 回退、独立性能基准和全协议故障注入测试后，才考虑加入可选 TCP-over-QUIC。现有 QUIC UDP relay 与 P2P 不受本决定影响。
